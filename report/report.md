## 1. Введение и постановка задачи

В проекте решается задача предсказания длительности поездки такси в Нью-Йорке. По параметрам поездки нужно предсказать `trip_duration` — время поездки в секундах.

Это задача регрессии. В качестве входных признаков используются время начала поездки, координаты посадки и высадки, количество пассажиров, идентификатор перевозчика и другие параметры.

Для оценки качества используется метрика **RMSLE**:

```math
RMSLE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(\log(1 + \hat{y_i}) - \log(1 + y_i))^2}
```

RMSLE выбрана потому, что длительность поездок распределена неравномерно: есть много коротких поездок и небольшое число очень длинных. Эта метрика снижает влияние выбросов и оценивает относительную ошибку прогноза.

## 2. Данные

Используется датасет **NYC Taxi Trip Duration**. В обучающей выборке есть информация о поездках такси и целевая переменная `trip_duration`.

Основные признаки:

| Признак | Описание |
|---|---|
| `vendor_id` | идентификатор перевозчика |
| `pickup_datetime` | дата и время начала поездки |
| `dropoff_datetime` | дата и время окончания поездки |
| `passenger_count` | количество пассажиров |
| `pickup_longitude`, `pickup_latitude` | координаты посадки |
| `dropoff_longitude`, `dropoff_latitude` | координаты высадки |
| `store_and_fwd_flag` | флаг сохранения данных перед отправкой |
| `trip_duration` | длительность поездки, целевая переменная |

В тестовой выборке нет `trip_duration`, так как это значение нужно предсказать.

## 3. Подготовка данных

Была выполнена базовая обработка данных:

- удаление выбросов по длительности поездки, координатам, количеству пассажиров и расстоянию;
- преобразование `pickup_datetime` в признаки `hour`, `day_of_week`, `month`, `is_weekend`;
- расчёт расстояния между точкой посадки и высадки — `distance_km`;
- кодирование `store_and_fwd_flag`;
- логарифмирование целевой переменной через `np.log1p(trip_duration)`.

Логарифмирование целевой переменной используется, потому что оно согласуется с RMSLE и уменьшает влияние очень длинных поездок.

Разбиение данных выполнялось до обучения моделей. Преобразования обучались на train-части и затем применялись к другим данным, чтобы избежать data leakage.

## 4. Baseline

В качестве baseline использовалась **Linear Regression**. Она нужна как простая точка сравнения для более сложных моделей.

| Модель | RMSLE |
|---|---:|
| Linear Regression | 0.5976 |

Baseline показал, что линейная модель недостаточно хорошо описывает зависимость длительности поездки от координат, расстояния и времени суток.

## 5. Эксперименты

Были протестированы несколько моделей: Linear Regression, KNN, Random Forest, Gradient Boosting, LightGBM, XGBoost и ансамбль XGBoost + LightGBM.

| № | Гипотеза | Проверка | Результат |
|---:|---|---|---|
| 1 | Линейная модель даст базовое качество | Обучена Linear Regression | RMSLE = 0.5976 |
| 2 | KNN сможет находить похожие поездки | Обучена KNN-регрессия | Качество хуже бустингов |
| 3 | Random Forest лучше уловит нелинейности | Обучен Random Forest | Лучше baseline, но хуже бустингов |
| 4 | Gradient Boosting улучшит качество | Обучен Gradient Boosting | Качество улучшилось |
| 5 | LightGBM хорошо подойдёт для табличных данных | Обучен LightGBM | Высокое качество и скорость |
| 6 | XGBoost даст лучший результат среди одиночных моделей | Обучен XGBoost | RMSLE = 0.3643 |
| 7 | Ансамбль улучшит результат | Усреднение XGBoost и LightGBM | RMSLE = 0.3639 |

Лучший результат среди одиночных моделей показал **XGBoost**. Финальным решением выбран ансамбль **XGBoost + LightGBM**, так как он дал наименьшую ошибку.

## 6. Финальная модель и интерпретация

Финальная модель — ансамбль **XGBoost + LightGBM**. Итоговое качество:

| Модель | RMSLE |
|---|---:|
| XGBoost | 0.3643 |
| XGBoost + LightGBM | 0.3639 |

Наиболее важные признаки:

| Признак | Интерпретация |
|---|---|
| `distance_km` | основной фактор длительности поездки |
| `hour` | отражает влияние времени суток и пробок |
| `dropoff_latitude` | отражает влияние района высадки |

Самым важным признаком оказалось расстояние между точками поездки, что логично для задачи предсказания длительности. Временные и географические признаки также влияют на результат, так как загруженность дорог зависит от времени суток и района города.

## 7. Деплой

Для проекта реализован локальный деплой модели. Он состоит из двух частей:

1. **FastAPI** — API для отправки запросов к модели.
2. **Streamlit** — пользовательский интерфейс для ручного ввода данных.

Структура файлов деплоя:

```text
app/
├── __init__.py
├── api.py
├── preprocessing.py
├── streamlit_app.py
└── models/
    ├── lgbm_model.pkl
    ├── xgb_model.pkl
    └── README.md

scripts/
└── train_and_save_models.py
```

Файл `preprocessing.py` отвечает за подготовку признаков: обработку даты и времени, расчёт расстояния, кодирование `store_and_fwd_flag` и формирование признаков для модели.

Файл `train_and_save_models.py` обучает XGBoost и LightGBM на `data/train.csv` и сохраняет модели в `app/models/`.

В `api.py` реализован endpoint `/predict`. Он принимает JSON с параметрами поездки:

```json
{
  "vendor_id": 1,
  "pickup_datetime": "2016-03-15 14:30:00",
  "passenger_count": 2,
  "pickup_longitude": -73.985428,
  "pickup_latitude": 40.748817,
  "dropoff_longitude": -73.98513,
  "dropoff_latitude": 40.758896,
  "store_and_fwd_flag": "N"
}
```

Пример ответа API:

```json
{
  "predicted_trip_duration_seconds": 578,
  "predicted_trip_duration_minutes": 9.63
}
```

Команда запуска FastAPI:

```bash
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Swagger доступен по адресу:

```text
http://127.0.0.1:8000/docs
```

Streamlit запускается командой:

```bash
streamlit run app/streamlit_app.py
```

Интерфейс доступен по адресу:

```text
http://localhost:8501
```

Внешний сервер не использовался, так как по заданию он необязателен. Локально деплой работает: API принимает запрос, модель возвращает прогноз, Streamlit отображает результат.
